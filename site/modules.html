4.7APEX modules

An APEX packages native code, Java and config into one signed, updatable file mounted at /apex/<name>. On a head unit it is useful for vendor components you want to update independently of a full OTA.

4.8Partition placement

Treble splits the image into partitions owned by different parties. Where a module installs is decided by one property:

PropertyInstalls toTypical owner / content
(none)/systemGoogle / AOSP framework. Avoid adding vendor code here.
system_ext_specific: true/system_extOEM framework extensions tightly coupled to system.
product_specific: true/productOEM apps, overlays, branding — per product line.
vendor: true (or soc_specific)/vendorSoC/board HALs, daemons, firmware, VINTF.
device_specific: true/odmBoard-variant customization on top of vendor.
vendor_available: trueboth /system and /vendor variantsLibraries needed on both sides.
recovery: true · ramdisk: true · vendor_ramdisk: truerecovery · generic ramdisk · vendor ramdiskEarly-boot tools and first-stage init modules.
⚠️
Warning

A vendor module may not link a system-only library and vice versa — Soong reports “dependency on non-vendor library” at generate time. This boundary is what keeps the vendor image working when system is updated.

4.9Getting a module onto the image

Defining a module only makes it buildable. It lands in an image when something reaches it from the product's install list:

PRODUCT_PACKAGES→module→required: […]→installed in $OUT/<partition>

Check the result with outmod acme.vehicle.bridge or by listing $ANDROID_PRODUCT_OUT/vendor/bin/hw/.
