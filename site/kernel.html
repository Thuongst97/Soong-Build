Kernel, GKI & Kleaf

The Android platform build does not compile the kernel. The kernel has its own source tree and its own Bazel-based build (Kleaf); the device tree then consumes the results as prebuilts. This split is the first of several “separate build, joined at the image” patterns you'll meet in a head unit.

⏱ 25 min read🎯 Intermediate🧰 repo · Bazel (Kleaf)

9.1GKI architecture

The Generic Kernel Image is one kernel binary per Android-kernel branch (e.g. android15-6.6), built and signed by Google. Everything SoC- or board-specific is a loadable module that may use only the symbols in the stable KMI (Kernel Module Interface).

GKI kernel

Core kernel + generic drivers. Ships in boot.img. Updated by Google's security releases without rebuilding vendor modules.

GKI modules

Google-built modules (e.g. some networking, virtio pieces) on system_dlkm where used.

Vendor modules

SoC, board and hypervisor drivers. Early ones in vendor_boot's ramdisk, the rest in vendor_dlkm.

ℹ️
Note

Automotive programs are often allowed more flexibility than phones (non-GKI kernels, extra symbols). Still, aligning with GKI pays off over a 10-year vehicle life: kernel security fixes then arrive as a drop-in boot.img.

9.2Getting the kernel source

Your SoC vendor normally provides a kernel manifest that adds its module sources (and sometimes a patched common). Keep it in your own local_manifests, exactly like the platform tree.

9.3Building with Kleaf

Kleaf wraps the kernel's Kbuild in Bazel rules: hermetic toolchains from prebuilts/, cached results and reproducible output. The legacy build/build.sh flow is gone from recent branches.

9.4Vendor modules

The Driver Development Kit (DDK) rules let you build an out-of-tree module against a GKI build without writing a Kbuild Makefile. Example: a driver for the hypervisor's shared-memory device.

9.5Device tree: DTB & DTBO

On bare metal, the bootloader passes a DTB describing the board, optionally patched by overlays from dtbo.img. A VM guest is different: the hypervisor describes the virtual machine — RAM, vCPUs, virtio-mmio devices, interrupts — and typically generates the guest's device tree from its VM configuration (Module 11).

9.6Dropping the kernel into the Android build

Copy the Kleaf output into a dedicated prebuilt project, then let the device tree pick it up. Version the directory by kernel branch so an upgrade is a one-line change.

device/acme/hu-kernel/6.6/ ├── Image # → boot.img ├── System.map vmlinux # for debugging only, not installed ├── vendor_ramdisk/*.ko # first-stage: virtio_blk, virtio_mmio, acme_ivc … ├── vendor_dlkm/*.ko # everything else └── modules.load # load order
