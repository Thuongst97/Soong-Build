Android Automotive Guest

Everything from Modules 01–09 comes together here: a device tree that turns AOSP into an Android Automotive VM. The guest sees virtual disks, a virtual console and a few passed-through devices; vehicle data arrives through a VHAL that talks to the hypervisor host.

13.1Android as a VM guest

Don't start from an empty directory. Two AOSP devices already solve most guest problems, and your SoC vendor usually ships a guest device tree for its graphics and audio stacks.

device/google/trout

Android Automotive on a hypervisor with virtio devices; VHAL forwards to a host-side server over the network/vsock. The closest public reference to this module.

Cuttlefish (auto)

aosp_cf_*_auto: a complete virtio-based automotive device. Good source for fstab, init and virtio kernel modules.

SoC vendor guest tree

Graphics, display, audio and codec HALs for your chip in a VM. Merge it as a separate namespace.

Why androidboot.boot_devices matters

First-stage init creates /dev/block/by-name/* links only for the device named here — the virtio-mmio disk the host exports at guest address 0x1c0b0000. That disk is a whole UFS LUN carrying its own GPT with every Android partition (Module 15.1).

13.6VHAL bridge to the vehicle

AOSP's reference VHAL is split in two: DefaultVehicleHal implements the AIDL IVehicle service (subscriptions, permissions, batching), and delegates to an IVehicleHardware implementation. You implement only the hardware side — here, a client that forwards property reads/writes to the host gateway over vsock. (AOSP also contains a gRPC-based IVehicleHardware, used by trout, if your host can run a gRPC server.)

💡
Tip

Define the vsock protocol (protobuf schema, property ID mapping, versioning) in one repository shared by the Android bridge and the QNX gateway. Build it with Soong (cc_library_static + protobuf) on the Android side and with qcc on the QNX side.

13.7Displays & audio routing

Displays

The composer HAL exposes the display pipes the host assigned to Android (center, passenger). CarService maps them to occupant zones through config_occupant_zones and config_occupant_display_mapping in an RRO. The cluster panel is not an Android display — the map reaches it through shared memory.

Audio

car_audio_configuration.xml maps audio contexts (music, navigation, call, alerts) to output devices. In a VM each device is a virtio-snd stream or vendor shmem channel mixed by the host DSP, where cluster chimes have priority.

13.8SELinux for guest services

Every new vendor service needs a label and the minimum permissions. Develop in userdebug, collect denials with adb logcat | grep avc, and turn them into rules — never ship permissive.
