Android.bp & the Blueprint Language

Android.bp looks like JSON and is deliberately almost as limited: no if, no loops, no functions. That limitation is what lets Soong parse 100,000 modules in seconds and reason about every variant. Learn the handful of constructs it does have.

⏱ 30 min read🎯 Beginner → Intermediate📂 build/blueprint · build/soong

3.1Syntax basics

A file is a list of modules. Each module starts with a module type, followed by a block of name: value properties. Every module needs a name that is unique across the tree (or within its namespace, Module 06).

  • Property names are snake_case; strings use double quotes only.
  • Paths in srcs are relative to the directory of the Android.bp, and accept globs: "src/**/*.cpp".
  • Soong finds every Android.bp in the tree automatically — there is no include.
  • Referencing another module's output uses ":module_name" in a source list (e.g. a filegroup or genrule).

3.3Variables & defaults

Variables are assigned at the top level. They are visible for the rest of the file and in Android.bp files of sub-directories. You may append with += only before the variable is first used; after that it is immutable.

Defaults modules are the reusable building block: a cc_defaults, java_defaults etc. holds common properties, and other modules pull them in with defaults:. Lists are concatenated (defaults first), scalar values set in the module win.

💡
Tip

Create one *_defaults per team or subsystem (compiler warnings, sanitizers, partition) and make every module use it. It is the cheapest way to keep hundreds of vendor modules consistent.

3.4Arch, target & multilib

Instead of conditionals, properties can be nested under keys that match a variant. Soong merges the matching block into the module for that variant only.

3.5Conditionals with select()

Since Android 15, a property can be a select() expression that picks a value from a configuration source. It is the modern replacement for many soong_config_module_type uses (Module 06) and the right tool for head-unit variants such as display layout or VM transport.

⚠️
Warning

Only properties marked configurable in Soong's Go code accept select(). Support grows with every release; if a property does not support it, Soong fails with a clear error and you fall back to soong_config_module_type.

3.6Visibility, licenses & namespaces

Visibility controls which directories may depend on a module — essential when several suppliers share one tree. Licenses are mandatory metadata: every module needs an applicable license, usually set once per directory with a package block.

Visibility ruleMeaning
//visibility:publicAnyone.
//visibility:privateOnly this Android.bp.
//dir:__pkg__Modules in exactly that directory.
//dir:__subpackages__That directory and everything below it.

3.8Formatting & conversion tools

bpfmt

Canonical formatter; many Gerrit hosts reject unformatted files. bpfmt -w Android.bp · bpfmt -d . to diff.

androidmk

Converts an Android.mk to a best-effort Android.bp: androidmk Android.mk > Android.bp. Review the result by hand.

bpmodify

Scriptable edits: bpmodify -m libfoo -property shared_libs -a libbar -w Android.bp.
