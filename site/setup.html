Host Setup, Source Sync & First Build

A reliable workstation and a reproducible checkout save more time than any build trick. This module takes you from a fresh Ubuntu machine to a booting Android Automotive emulator build.

⏱ 25 min read · several hours of syncing🎯 Beginner🐧 Ubuntu 22.04 / 24.04 LTS

2.1Workstation requirements

Note

The head-unit workspace in this handbook holds four source trees (Android, QNX host/cluster, Yocto, firmware). Budget disk for all of them — see Module 10 for the layout.

2.3The repo tool & manifests

AOSP is ~1,000 git repositories. repo checks them out according to an XML manifest. Your company will add its own repositories (device tree, vendor HALs, BSP blobs) with local manifests rather than forking Google's.

2.4Syncing the source

OptionEffect
-cFetch only the current branch of each project.
--no-tagsSkip tags — much less data.
--partial-cloneFetch large file contents lazily.
-g <groups>Sync only projects in these manifest groups (e.g. drop darwin).
--reference=/mirrorBorrow objects from a local mirror (repo init --mirror) shared by the team or CI.

2.5envsetup.sh helpers

Every shell that builds must first source build/envsetup.sh. Besides lunch and m, it defines navigation and search helpers that are much faster than a raw grep -r over the tree.

2.6Choosing a target with lunch

A build target has three parts: product (what goes in the image), release (which feature-flag values apply) and variant (how debuggable it is).

aosp_cf_x86_64_auto-trunk_staging-userdebug
VariantUseProperties
userProductionNo root, ro.debuggable=0, adb off by default, full optimization.
userdebugDaily development & validationLike user but with adb root, debugging tools and permissive debugging options. The default choice.
engEarly bring-upExtra tools, fewer optimizations (e.g. no dex pre-optimization), slower at runtime.
ℹ️
Note

Since Android 15 the release part is mandatory. trunk_staging enables in-development features; a shipped branch also has its own release (run list_releases after lunch). Products for your head unit are added by your own AndroidProducts.mk — Module 05.

2.8Reproducible builds in a container

A head-unit program lives for years. Pin the host environment in a container image so a build from three years ago can be reproduced. Mount source, out/ and ccache from the host so they survive container restarts.
