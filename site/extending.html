Customizing & Extending Soong

Sooner or later a vendor tree needs “build this differently on board B” or “two suppliers both ship a libcamera_hal”. Soong has a ladder of mechanisms for that — climb it from the bottom and stop as early as you can.

6.2Soong namespaces

A soong_namespace module at the top of a directory makes all module names below it private to that namespace. Only namespaces listed in PRODUCT_SOONG_NAMESPACES are built and visible to Make, so two board families can define the same module names side by side.

ℹ️
Note

Modules outside any namespace live in the global (root) namespace and are always visible. Forgetting to add a namespace to PRODUCT_SOONG_NAMESPACES gives “module not found” — even though the Android.bp is right there.

6.3soong_config_module_type

Defines a new module type that wraps an existing one and lets selected properties change with Soong config variables. Before select() this was the only supported way to put conditionals in Android.bp.

6.4Writing a Go module type

Soong is Go, and a bootstrap_go_package with pluginFor: ["soong_build"] is compiled into it. A load hook can compute properties in code before the module is processed.

⚠️
Warning

Soong's Go API is internal and changes every release. Recent AOSP versions also validate plugins against an allowlist; out-of-tree plugins need BUILD_BROKEN_PLUGIN_VALIDATION in BoardConfig.mk. Every plugin is a migration task on each Android upgrade — use one only when select() and config module types truly cannot express the logic.

6.6Best practices

One namespace per supplier

SoC vendor, Tier-1 and OEM code each in their own namespace with explicit imports. Name clashes become impossible and dependencies become visible.

Config in the product, not the code

Every board difference is a Soong config variable set in device.mk. Never test TARGET_PRODUCT names inside modules.

Keep AOSP pristine

Change AOSP behaviour through overlays, config and your own modules. Each AOSP patch costs you on every upgrade; track the ones you must keep.

Validate early

Run m nothing and bpfmt -d in pre-submit. Most build breaks are caught in a minute instead of after a two-hour build.
