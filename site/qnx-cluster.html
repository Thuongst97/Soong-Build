Module 12 · Head-unit SoC

QNX Instrument Cluster Guest

The cluster is the one screen the driver must be able to trust at all times. It runs as its own QNX guest with dedicated cores, boots in about a second and keeps working if Android crashes or reboots. Its build is small — a single IFS — but its requirements shape the whole system.

⏱ 20 min read🎯 Advanced🧰 QNX SDP · Screen · mkifs

12.1What the cluster VM owns

Safety-relevant content

Speed, gear, telltales (brake, airbag, ABS…), warnings and chimes. Usually rated ASIL-B and developed to ISO 26262.

Comfort content

Trip computer, media now-playing, phone — and the navigation map rendered by Android and shared through memory.

The cluster panel

Its display pipe (and often a head-up display) belongs to this VM alone.

Independence

It never waits for Android. If the map stream stops, the cluster shows its own fallback view.

12.2Cluster guest image

A QNX guest is built exactly like a QNX target image, but with the guest startup from the hypervisor's guest BSP and virtio drivers instead of real hardware drivers.

12.3Screen & display ownership

Screen is QNX's compositing windowing system. The cluster HMI (built with a tool such as Kanzi, Qt or a vendor HMI engine) renders into Screen windows; Screen composes them onto the cluster display, including a window fed by Android's navigation frames.

Android nav app→ shmem →acme-nav-receiver (Screen stream)→Screen compositor→cluster panel
ℹ️
Note

How the GPU is shared between VMs is SoC-specific: some vendors give each VM a hardware GPU context, others render guest content through the host. Either way the cluster's GPU work must be prioritised — configure it in the vendor graphics stack, not in Soong.

12.4Early features: telltales & RVC

Two features must work long before Android is up:

Telltales

A minimal renderer draws regulated indicators from the first vehicle signal. The full 3D HMI fades in later; the telltale layer stays authoritative.

Early rear-view camera

The host or cluster captures the camera and shows it on the center display when reverse is selected. Once Android's EVS service is ready it can take over, with a handshake so the picture never blinks.

12.5Freedom from interference

ISO 26262 requires that lower-integrity software (Android, QM) cannot disturb the cluster. The hypervisor provides the mechanisms; your configuration must actually use them:

InterferenceMechanismWhere configured
Spatial (memory)Separate guest RAM, SMMU for DMA, read-only shared memory towards the clustercluster.qvmconf, host SMMU setup
Temporal (CPU)Pinned cores, priorities, scheduling budgetscpu lines in qvm configs
CommunicationEnd-to-end protection (counter, CRC) on vehicle signals; timeoutsacme-signals and the host gateway
LivenessWatchdog vdev monitored by the host health monitorqvm config + host services
Display contentDisplay controller CRC check of the telltale regionVendor display driver on the host
